# ПЛАН СБОРКИ (источник истины при потере контекста)

Строим приложение «Студия» строго по `design/DESIGN.md` (стек — §6, утверждён)
и прототипу `design/studio-flow.html` (внешний вид и взаимодействия 1:1:
светлая тема, рейл слева, меню «⋯» на фразах — БЕЗ постоянных кнопок у фраз).
Пользователь оставил работу на автономное выполнение: «делай всё сразу,
не отходи от дизайна». Проверит результат позже.

## Архитектура (решено, не менять)

```
translator/
  app.py        FastAPI + uvicorn, WS /ws для live-событий, REST, статика
  engine.py     звук: sounddevice 16kHz → VAD-сегментер;
                ASR двухступенчатый faster-whisper int8:
                  черновик small (окно ≤5с, каждые ~0.7с, beam 1)
                  финал large-v3-turbo (по паузе VAD, beam 5)
                перевод: deep-translator Google; фолбэк argos es→en→ru
                (если пакетов нет — показываем испанский оригинал);
                запись лекции в flac (soundfile), 16k mono
  db.py         SQLite: courses, lectures, phrases(t0,t1,es,ru,mark),
                notes(t,text), words, settings(k,v), chats
  llm.py        один OpenAI-совместимый клиент:
                локально Ollama http://localhost:11434/v1, модель qwen3:4b
                (фолбэк llama3.2:3b); облако: base_url+key+model из настроек
                (совместимо с Uno LLM Gateway api.getuno.xyz/llm).
                Роли: чат с контекстом транскрипта, catch-up каждые 10 мин,
                конспект, объяснение фраз/терминов.
                АГЕНТ (только облако!): tools = files (только внутри
                workspace-папки), web_search (DuckDuckGo html), fetch_url,
                terminal (КАЖДАЯ команда ждёт «Разрешить» в UI через
                threading.Event + WS), share_file (POST multipart
                https://api.getuno.xyz/api/v1/deploy → {slug}.uno4.dev).
                Локальной 4B никаких tools.
  static/       index.html + app.css + app.js — интерфейс из прототипа,
                подключённый к API/WS
  PLAN.md       этот файл
```

Бюджет ресурсов (M1 Pro 16 ГБ, лимит 50–60%): small 0.5 + turbo 1.5 +
qwen3:4b 2.6 + приложение ≈ 5.3 ГБ — ок. LLM через Metal, keep_alive 10m.

## Экраны (из прототипа, все обязательны)

1. Старт: выбор предмета (+создание), полоска уровня микрофона
   («вас слышно»), «Начать лекцию».
2. Live: хедер (● таймер, предмет, уровень, «Свернуть в полоску»-заглушка,
   ■ Стоп); лента финальных фраз (RU крупно/ES мелко/время);
   catch-up-карточки; live-зона снизу (ES по словам + черновой перевод);
   меню «⋯»: Важное ⌘1 / Не поняла ⌘2 / В заметки ⌘L / Объяснить в чате /
   Копировать; клик по ES-слову → поповер (перевод, «+ В словарь»).
   Правая панель: Заметки (текст, автосохранение, привязка к таймкоду) |
   Перевод (ru⇄es⇄en, «Показать крупно» во весь экран) |
   Словарь (слова лекции) | Чат ИИ (локально/облако, быстрые кнопки).
3. Итог после «Стоп»: статистика, «Сделать конспект» / «Позже».
4. Повторение: <audio> плеер + транскрипт с перемоткой по клику и
   подсветкой текущей фразы; справа Конспект (генерится LLM, редактируемый,
   сохраняется) | Мои заметки; экспорт: Markdown-файл, печать/PDF,
   «Поделиться» (Uno hosting).
5. Библиотека: предметы, таблица лекций, поиск по всем транскриптам.
6. Словарь: таблица слов, экспорт Anki (tsv).
7. Конспекты: список, открыть.
8. Настройки: микрофон, точность (быстро=small / сбаланс=small+medium /
   макс=small+turbo), язык перевода, локальная LLM (url+модель),
   облачная LLM (base_url, api_key, model), тумблер «режим агента»,
   ключ Uno для шеринга, папка данных.

## Правило перезапуска сервера (выучено на граблях 10.08)
pkill/kill из sandboxed-шелла МОЛЧА не убивают процессы вне песочницы —
одновременно крутилось три app.py, запросы попадали в разные билды
(выглядело как случайные зависания). Поэтому: любые pkill и запуск
сервера — только unsandboxed; после рестарта проверять
`pgrep -f "[a]pp.py" | wc -l` == 1; перед рестартом — GET /api/state,
чтобы не убить идущую лекцию. Лишние PID на :8899 в lsof — клиенты
(Chrome/Uno Work), это нормально.
ВАЖНО (грабли 10.08 №2): проверка state должна быть УСЛОВИЕМ (if …
running == false → kill), а не просто выводом в той же команде — иначе
kill выполнится даже при идущей лекции (так была оборвана живая
лекция 3 пользователя; фразы и flac уцелели — flush каждые 2 c,
ended_at проставлен вручную).

## Баг «вечная плашка паузы» (разобран по скриншоту; код готов)
Симптом: плашка «на паузе» видна, а движок слушает; ▶ не помогает.
Причина — цепочка: (1) пауза в конце прошлой лекции показала плашку;
(2) Engine.stop() сбрасывает paused БЕЗ события в UI; (3) старт новой
лекции не прятал плашку (display остался с прошлой); (4) resume() при
непаузе молча выходил — «Продолжить» ничего не подтверждал.
- [x] btn-start: setPaused(false) при старте новой лекции
- [x] resume(): при «не на паузе» шлёт paused{on:false} (подтверждение);
      при паузе — СНАЧАЛА открывает микрофон, потом снимает паузу
      (иначе тихий рассинхрон при ошибке устройства)
- [x] tick теперь несёт paused — UI самокорректируется за ≤1 с
- [x] чат: ответы ИИ рендерятся маркдауном (mdRender), а не сырым
      текстом с ** и -; компактные стили списков в пузырях
- [ ] бэкенд-фиксы активируются после рестарта (лекция 8 шла — ждёт
      фоновый скрипт); фронт — после перезагрузки страницы
